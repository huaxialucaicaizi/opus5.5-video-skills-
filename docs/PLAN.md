# 实施计划与执行记录

## 计划（开发前制定）
1. 调研参考仓库与其链接的源码仓库，逐个核查许可 → `docs/research.md`、`SOURCES.md`
2. 共享规格：任务 Schema、分镜 Schema、风格 tokens、验收清单
3. 渲染核心：框架无关的确定性引擎 + HTML 播放器契约 + Playwright 渲染器 + 原创配乐合成
4. 校验：规格、版式（渲染期文字框）、成片技术参数、确定性、QA 报告汇总
5. 15 s 案例：分镜 → 联系表 → 迭代 → MP4 → QA → 审片
6. 4 个 Skill、Remotion 包装、footage 工具、三种 Agent 接入
7. 跨 Agent 测评：任务集、评分器、校准、实际运行
8. 从干净检出复验，打包

## 关键决策
| 决策 | 原因 |
|---|---|
| 主路线 HTML-Canvas，不是 Remotion | 零依赖、许可无条件、任何能跑 Node+Chromium 的 Agent 都能用；开发环境装不上 Remotion |
| 分镜 JSON 直接驱动渲染（场景 = 组件名 + 参数） | 计划和成片不会漂移；校验器能在渲染前发现大部分问题 |
| 文字统一走 `f.text()` 并上报文字框 | 安全区、字号、重叠可以从**实际渲染结果**判断，而不是猜 |
| 转场由 composition 统一负责，场景不自己淡出 | 审片时发现两者叠加会产生约 0.25 s 空帧 |
| 配乐程序化合成 | 示例片零外部素材，许可清楚 |
| Skill 正文与 Agent 无关，差异放进安装脚本与文档 | 三个 Agent 的发现目录、调用方式、权限模型都不同 |
| 评分器用测评端校验器重新采证 + 完整性闸门 | 不信任被测 Agent 关于自己的报告 |

## 开发中被测试/审片发现并修复的问题
| 发现方式 | 问题 | 修复 |
|---|---|---|
| 联系表 v1 | 字号太小、标点开头换行、标题孤字 | 放大字阶；标点避头；`fit` 自动缩放 |
| `validate_spec` S3 | 注释停留 0.9 s < 需要 1.0 s | 调整出现时间 |
| `layout_check` V1 | 相机推近后标签越出安全区 2 px；注释进入底部 UI 区 33 px；结论标题贴边 | 加大边距；上移；`maxWidth` 留余量 |
| 接缝帧条 | s1→s2 约 0.25 s 近乎空白；push/fade 双重曝光 | 场景不再自淡出；转场改为分段出/入 |
| 渲染器自查 | 可续渲会复用代码修改前的旧帧 | 源文件指纹，变化即清空旧帧 |
| footage 合成检查 | 字幕压在画中画上 | 画中画默认上移避开字幕带；新增 `reserved_regions` + V4 |
| 评分器校准 | 什么都不做在 E4/E5 拿 40 分；环境变量导入顺序导致组件根目录错误 | 按预埋缺陷计分、意图分乘修复率；先设环境变量再导入 |
| 评分器校准 | `footage.py` 流复制输出没有 faststart | 所有复制路径加 `+faststart` |

跨模型测评又发现并修复了 6 个问题（风格规则歧义、`append-loop` 换行跳动、横屏风格缺失、文字溢出容器未检测、E1 可复用示例、结尾未呼应），见 [`TEST_RESULTS.md`](TEST_RESULTS.md) 第 7 节。
